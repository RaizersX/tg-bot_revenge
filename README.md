# 🤖 Revenge — Telegram-бот для подготовки к Python

> (ДДЗ). Интерактивный квиз-бот в Telegram для изучения теоретической части Python с поддержкой трёх типов заданий и административной панелью.

---

## 📌 Описание проекта

**Фибик** — это Telegram-бот, который помогает пользователям осваивать программирование на Python через интерактивные задания. Бот поддерживает три типа вопросов: выбор из вариантов, открытые вопросы и задания с кодом, проверяемым на тестах. Администратор может добавлять новые вопросы прямо из чата.
Так же бот разработан чтобы подготовиться к контрольной по Python,если она будет в формате Revenge.

## 🎯 Реализованный функционал

### 👤 Для пользователя

- **Выбор уровня сложности** — три уровня (Лёгкий / Средний / Сложный) через inline-клавиатуру
- **Три типа заданий:**
  - 🔘 **С вариантами ответов** — inline-кнопки, мгновенная проверка
  - 💬 **Открытые вопросы** — пользователь вводит ответ текстом
  - 💻 **Задания с кодом** — пользователь отправляет код, бот проверяет на наборах тестов (input/output)
- **Последовательное прохождение** — очередь вопросов перемешивается, после прохождения всех вопросов уровня предлагается выбрать новый
- **Объяснения** — после каждого ответа показывается правильный ответ и пояснение

### 🔧 Для администратора

- **Пошаговое добавление вопросов** через FSM-мастер (`/add_question`):
  1. Выбор типа вопроса (1 / 2 / 3)
  2. Ввод текста вопроса
  3. Ввод вариантов ответа / правильного ответа / шаблона кода + тестов
  4. Ввод номера правильного ответа (для вариантов)
  5. Объяснение
  6. Выбор уровня сложности
- **Просмотр статистики** (`/view_questions`) — количество вопросов по уровням
- **Админ-панель** — кнопка в ReplyKeyboard (видна только админу)
- Вопросы сохраняются в `questions.json` автоматически

## 🔐 Система прав доступа

Администратор определяется по Telegram User ID, заданному в переменной окружения `USER_ID`. Поддерживается несколько ID через запятую:

```env
USER_ID=123456789,987654321
```

Проверка выполняется функцией `is_admin()` перед каждым защищённым действием.

## 🚀 Запуск

### 1. Клонирование и установка зависимостей

```bash
git clone <repository_url>
cd fibik-bot
pip install -r requirements.txt
```

### 2. Настройка переменных окружения

Создайте файл `.env` в корне проекта:

```bash
python main.py
```

## 📦 Структура вопроса в `questions.json`

### Варианты ответов
```json
{
  "question": "Что выведет print(type([]))?",
  "options": ["<class 'list'>", "<class 'tuple'>", "<class 'dict'>"],
  "correct_index": 0,
  "explanation": "[] — это литерал списка, его тип — list.",
  "level": 1
}
```

### Открытый вопрос
```json
{
  "question": "Какая функция возвращает длину строки?",
  "correct_answer": "len",
  "explanation": "len() — встроенная функция для получения длины последовательности.",
  "level": 1
}
```

### Задание с кодом
```json
{
  "question": "Напишите функцию, которая возвращает сумму элементов списка.",
  "code_template": "def sum_list(lst):\n    # ваш код\n    pass",
  "tests": [
    {"input": "[1, 2, 3]", "output": "6"},
    {"input": "[]", "output": "0"}
  ],
  "explanation": "Можно использовать встроенную функцию sum().",
  "level": 2,
  "type": "code_test"
}
```

## 🔄 Машина состояний (FSM)

Проект использует конечный автомат aiogram для управления многошаговыми сценариями:

### QuizState
| Состояние | Назначение |
|---|---|
| `waiting_for_level` | Ожидание выбора уровня сложности |
| `waiting_for_answer` | Ожидание ответа на вопрос (варианты / открытый) |
| `waiting_for_code` | Ожидание кода от пользователя |

### AddQuestionState
| Состояние | Назначение |
|---|---|
| `waiting_for_question_type` | Выбор типа вопроса |
| `waiting_for_question` | Ввод текста вопроса |
| `waiting_for_options` | Ввод вариантов ответа |
| `waiting_for_correct_index` | Ввод номера правильного варианта |
| `waiting_for_correct_answer` | Ввод правильного ответа (открытый) |
| `waiting_for_code_template` | Ввод шаблона кода |
| `waiting_for_tests` | Ввод тестов (input/output) |
| `waiting_for_explanation` | Ввод объяснения |
| `waiting_for_level` | Выбор уровня сложности |

## 🛡️ Обработка ошибок

- Отсутствующий `questions.json` — бот запускается с пустой базой, предупреждение в лог
- Некорректный JSON — ошибка в лог, бот работает без вопросов
- Пустая база при старте квиза — пользователю выводится сообщение «в разработке»
- Невалидный ввод админа (не число, выход за диапазон) — повторный запрос
- Все исключения в хендлерах логируются через `logger.error(..., exc_info=True)`
